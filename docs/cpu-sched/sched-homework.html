Q1

Response and turnaround time for three jobs of length 200, with SJF and FIFO.

python3 scheduler.py -p SJF -l 200,200,200 -c python3 scheduler.py -p FIFO -l 200,200,200 -c
Answer

Both give the same schedule: response 0, 200, 400 (avg 200); turnaround 200, 400, 600 (avg 400).

With equal lengths SJF has nothing to reorder, so it runs the jobs in arrival order, exactly like FIFO.

Q2

Same, with jobs of length 100, 200 and 300.

python3 scheduler.py -p SJF -l 100,200,300 -c python3 scheduler.py -p FIFO -l 100,200,300 -c
Answer

Still identical: response 0, 100, 300 (avg 133.33); turnaround 100, 300, 600 (avg 333.33).

The jobs already arrive shortest-first, so FIFO's order happens to be SJF's order. Try -l 300,200,100 to see them split (Q4).

Q3

Same, but also with the RR scheduler and a time slice of 1.

Answer

RR with q=1: response 0, 1, 2 (avg 1) for both workloads. Turnaround gets much worse: avg 599 (equal jobs: all finish at the very end, 598–600) and 465.67 for 100/200/300 (298, 499, 600).

The fairness trade-off from the chapter: RR is great for response, one of the worst for turnaround.

Q4

For what types of workloads does SJF deliver the same turnaround times as FIFO?

python3 scheduler.py -p FIFO -l 100,200,300 -c # arrives shortest-first python3 scheduler.py -p SJF -l 100,200,300 -c python3 scheduler.py -p FIFO -l 300,200,100 -c # arrives longest-first python3 scheduler.py -p SJF -l 300,200,100 -c
Arrival orderFIFO avg turnaroundSJF avg turnaround
100, 200, 300 (shortest first)333.33333.33
200, 200, 200 (all equal)400400
300, 200, 100 (longest first)466.67333.33
Answer

When the jobs already arrive in order of non-decreasing length (shortest first, or all the same length). Then FIFO's order is SJF's order, so the schedules and turnaround times are identical.

Any time a longer job arrives before a shorter one, SJF reorders and wins (the convoy effect FIFO suffers from).

Q5

For what types of workloads and quantum lengths does SJF deliver the same response times as RR?

python3 scheduler.py -p SJF -l 100,200,300 -c python3 scheduler.py -p RR -q 1 -l 100,200,300 -c # small slice: differs python3 scheduler.py -p RR -q 300 -l 100,200,300 -c # slice ≥ longest job: same python3 scheduler.py -p RR -q 200 -l 200,200,200 -c # equal jobs, slice = length: same
Answer

When the quantum is at least as long as every job (q ≥ max length) and the jobs arrive shortest-first. Each job then finishes within its first slice, so RR never preempts and degenerates into FIFO, which equals SJF for that arrival order (Q4).

  • 100, 200, 300 with q=300: avg response 133.33, same as SJF.
  • 200, 200, 200 with q=200: avg response 200, same as SJF.
  • Any smaller q preempts, and RR's response drops below SJF's.
Q6

What happens to response time with SJF as job lengths increase? Use the simulator to show the trend.

printf '%s\n' 100 200 300 400 500 | xargs -I{} sh -c 'printf "L={} "; python3 scheduler.py -p SJF -l {},{},{} -c | grep Average'

Three equal jobs of length L. Simulator output: L=100 → 100, 200 → 200, 300 → 300, 400 → 400, 500 → 500.

Answer

Response time grows linearly with job length. A job's response is the total length of every job that runs before it, so longer jobs mean longer waits for the ones behind them.

response(job k) = sum of lengths of jobs before it

For N equal jobs of length L: responses are 0, L, 2L, …, (N−1)L, so the average is (N−1)·L / 2 (= L for N=3).

Q7

What happens to response time with RR as quantum lengths increase? Write an equation for the worst-case response time, given N jobs.

printf '%s\n' 1 5 10 20 50 100 | xargs -I{} sh -c 'printf "q={} "; python3 scheduler.py -p RR -q {} -l 100,100,100 -c | grep Average' python3 scheduler.py -p RR -q 10 -l 100,100,100,100,100 -c # N=5: last job's response = 40

Three jobs of length 100. Simulator output: q=1 → 1, 5 → 5, 10 → 10, 20 → 20, 50 → 50, 100 → 100. Past q=100 the jobs finish in one slice and RR behaves like FIFO, so it stays flat.

Answer

Response time grows linearly with the quantum: each job waits one full slice for every job ahead of it in the queue. Once q reaches the job length, it stops growing (RR has become FIFO).

The last of N jobs that arrive together waits for N−1 slices:

worst-case response = (N − 1) · q

  • N=5, q=10 → 40, matching the simulator (responses 0, 10, 20, 30, 40).
  • If a job is shorter than q it gives up the CPU early, so more precisely: sum of min(q, length) over the jobs ahead.
  • With a context-switch cost c, it becomes (N − 1) · (q + c); see Amortizing the Context Switch.
