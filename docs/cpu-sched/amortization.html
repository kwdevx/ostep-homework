Amortizing the Context Switch

When an operation carries a fixed cost every time it happens, do it less often, so each payment covers more useful work. In Round Robin the fixed cost is the context switch, and the lever is the time slice.

The math

Each turn is one slice of real work plus one switch:

overhead = switch / (slice + switch)

The switch cost is fixed, so a bigger slice shrinks its share. The book rounds this to switch / slice: 1ms per 10ms ≈ 10%, per 100ms < 1%.

What a "switch" really costs

  • Direct: saving and restoring registers, switching the kernel stack and page tables.
  • Hidden: the new job starts with cold CPU caches, TLB and branch predictors, and runs slowly until they warm up. This is often the bigger part.

The same trick elsewhere

  • Buffered I/O: collect many small writes, then do one disk write.
  • Batching system calls or network packets: one crossing, many items.
  • Memory allocators: grab a big chunk from the OS, hand out small pieces.

Always the same shape: a fixed cost per operation, paid less often, spread over more work. The price is usually latency.
